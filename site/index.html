Most AI product manager roles want judgment about AI, not a model-building background.

Every week, code pulls every product, program and TPM opening from 36 AI and tech companies, and a decision model labels each one. Below is this week's run, drawn to scale.

By Gurnek Khaira, built with AI coding agents · Source on GitHub

Code computes facts. Jev judges meaning.

Anything a regex can get right stays in code: pay ranges, the remote flag, and whether a role can be done from Toronto or elsewhere in Canada. Jev, TypeSafe's decision model, answers only the questions that need judgment: what kind of role it is, whether the product is AI, the seniority, and whether ML, hands-on AI skills or an engineering background is a must-have.

Each answer comes with a probability. Code combines them into buckets, and anything under 0.6 confidence goes to review instead of a guess.

An early version asked the model for location. It labeled Vancouver roles as US-only, so location moved to code.

How far to trust the labels

I labeled 40 postings by hand and compared them with Jev. The question that matters most for this page is whether a role belongs in an AI bucket at all.

32 of 36agreed on AI bucket or not (89%). The other 4 went to review.
15 of 18on the half I labeled blind, before seeing Jev's answers

Seniority was within one level on all 40. "AI or not" merges AI-native and AI-platform, which is how the buckets use it; the three-way answer matched 18 of 40. Because the set is stratified by bucket, these numbers describe each bucket, not a random posting. The hands-on AI skills wording was written after my labels, so that row is not a held-out score.
